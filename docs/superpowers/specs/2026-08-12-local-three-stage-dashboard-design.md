# 本地六均线三阶段仪表盘设计

## 1. 目标

把当前 `reports/okx-three-stage-screener/` 的 Markdown 与 CSV 结果变成一个打开即用的本地网页，降低阅读成本，并允许用户在网页中启动一次新的 OKX 全市场扫描。

仪表盘只解决以下问题：

- 清晰查看四阶段正式状态与“接近下一阶段”观察合约。
- 从候选卡片一键跳转到用户已配置好指标的 Bitget 合约页面。
- 统一以北京时间显示扫描时间、突破时间、回踩时间与下一可执行时间。
- 保留扫描过程、失败原因和上一次成功结果，避免误以为页面空白就是没有机会。

仪表盘不自动下单、不连接交易账户、不修改策略参数，也不把实时形态快照表述为盈利证明。

## 2. 技术方案

采用项目现有 Freqtrade Docker 镜像内已安装的 FastAPI、Uvicorn 与 Jinja2，不新增第三方依赖。

新增独立 `dashboard` Compose service：

- 监听本机 `127.0.0.1:8787`，不暴露到局域网或公网。
- 复用当前项目目录挂载和 Python 环境。
- 启动本地 FastAPI 服务并读取三阶段报告产物。
- 扫描任务在同一容器内调用现有扫描逻辑，不启动嵌套 Docker。

提供一个启动脚本：启动 dashboard service、等待健康检查成功，然后使用 macOS 默认浏览器打开 `http://127.0.0.1:8787`。

## 3. 页面结构

页面使用深色交易终端视觉，保持高对比度和宽屏信息密度，同时兼容窄屏。

### 顶部状态区

- 页面标题：六均线三阶段筛选器。
- 当前北京时间，按秒更新。
- 上次成功扫描时间，明确标注 `北京时间 UTC+8`。
- live 合约数、符合上市时间的合约数、行情请求错误数。
- “立即重新扫描”主按钮。
- “仅使用已收盘K线”“人工辅助，不自动开仓”状态标签。

### 正式阶段区

按执行紧迫度固定排序：

1. 回踩确认 `entry_confirmed`
2. 等待第一次回踩 `wait_first_pullback`
3. 4H已突破、15m重新缠绕 `ready_4h_breakout_15m_coiled`
4. 4H与15m同时缠绕 `watch_both_coiled`

每个阶段显示数量、含义和候选卡片。空阶段显示明确的空状态，不隐藏标题。

### 接近下一阶段

单独使用橙色观察区，展示4H结构已出现但15m尚未满足条件的合约。必须显示缺少的条件，例如：

- 等待15m形成新缠绕。
- 15m等待已经过期，仅供复盘。

该区域始终标注“不属于正式候选”。

### 候选卡片

按状态显示可用字段：

- 合约、方向、日线偏向。
- 4H与15m缠绕分。
- 4H与15m密集区上下沿。
- 4H突破、15m突破、第一次回踩、下一可执行时间。
- 初始止损。
- 当前缺少条件或取消原因。

每张卡片提供“在 Bitget 查看”按钮，并在新标签页打开。

## 4. Bitget 链接规则

OKX instrument 形如 `LINK-USDT-SWAP`，页面链接转换为：

```text
https://www.bitget.com/zh-CN/futures/usdt/LINKUSDT
```

转换规则：取 `-USDT-SWAP` 前的 base，保留字母和数字，拼接 `USDT`。链接只用于导航，不代表 Bitget 一定存在同名合约。

如果 Bitget 返回不存在的产品，由 Bitget 页面自行提示；仪表盘不把跳转成功当成该合约可交易证明。

## 5. 时间校准

后端保存和计算仍使用 UTC，避免破坏已有因果状态机；展示层统一转换到 IANA 时区 `Asia/Shanghai`。

页面必须区分：

- 当前北京时间：浏览器每秒更新。
- 上次成功扫描时间：来自 manifest 的 `retrievedAt`。
- K线事件时间：来自 CSV 的状态字段，转换后显示 `YYYY-MM-DD HH:mm`。
- 下一可执行时间：同样显示北京时间，并保留“仅下一根15m开盘前有效”的提示。

前端不依赖浏览器本机时区做转换，而是接收后端已经转换好的北京时间字符串，避免用户系统时区变化造成歧义。

## 6. 扫描交互与数据流

### 初次打开

1. 后端读取 `run-manifest.json` 与 `latest.csv`。
2. 将所有时间转为北京时间。
3. 按四阶段与观察区组织页面数据。
4. 如果产物不存在，页面显示“尚未完成首次扫描”，但服务仍可使用。

### 点击立即重新扫描

1. 前端向后端发送一次扫描请求。
2. 后端使用进程内互斥锁确保同一时间最多一个扫描任务。
3. 页面立即显示“扫描中”和开始时间，按钮禁用。
4. 前端轮询扫描状态，显示三个阶段：日线、4H、15m。
5. 扫描完成后重新读取正式产物并刷新页面。

### 失败处理

- 扫描失败不删除或覆盖上一次成功页面数据。
- 页面显示失败时间和简短错误。
- 后端记录有限长度的标准输出/错误，禁止把环境变量、密钥或完整异常对象暴露到网页。
- 重复点击扫描时返回当前任务状态，不启动第二个任务。

## 7. 文件边界

计划新增或修改：

- `dashboard/app.py`：FastAPI 路由、报告读取、时间转换和扫描任务状态。
- `dashboard/templates/index.html`：页面结构。
- `dashboard/static/dashboard.css`：视觉样式与响应式布局。
- `dashboard/static/dashboard.js`：北京时间、扫描按钮和状态轮询。
- `scripts/open_three_stage_dashboard.sh`：一键启动并打开浏览器。
- `docker-compose.yml`：新增只绑定本机的 dashboard service。
- `tests/test_three_stage_dashboard.py`：链接、时区、分组、扫描锁与错误保留测试。
- `reports/okx-three-stage-screener/README.md` 与 `PROJECT_CONTEXT.md`：中文使用说明和交接。

旧 `reports/okx-screener/` 和旧三阶段 Markdown/CSV 继续保留。网页是新的显示与操作层，不改变研究数据格式。

## 8. 安全边界

- 服务只绑定 `127.0.0.1`。
- 无交易所密钥、登录、下单、仓位或资金接口。
- Bitget 只通过普通 HTTPS 链接在新标签页打开。
- 扫描API不接受任意命令、路径或策略参数；只触发固定三阶段扫描。
- 页面对CSV和错误文本做HTML转义。

## 9. 验收标准

- 一条命令启动服务并自动打开本地网页。
- 页面首次加载能显示现有四阶段结果与观察列表。
- 所有时间明确显示为北京时间，且 UTC→UTC+8 转换测试通过。
- `LINK-USDT-SWAP` 的按钮指向 `https://www.bitget.com/zh-CN/futures/usdt/LINKUSDT`。
- 点击扫描后不会重复启动，完成后自动刷新，失败时仍保留上次成功结果。
- 手机与桌面浏览器均可阅读；桌面优先展示完整交易字段。
- 全量测试通过，旧扫描报告目录未被意外修改或提交。
